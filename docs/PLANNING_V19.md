# kakeibo v1.9.0 資金計画 (開発ブランチ)

## 役割と境界
既存の月次予算・積立・ほしいもの機能は変更せず、「資金計画」タブを追加します。口座残高・引落時期を使った資金繰りではありません。月別の経済収支余剰と別途計上する予定支出・財源だけを合算します。

## 構成
- `planning.html`: v0.3.1モックを製品向けへ変更した独立UI。表示とシナリオ・プリセット管理を担当。CSSとDOMはiframeで隔離。
- `src/app/85_planning_bridge.part.js`: `KakeiboPlanningBridge`。家計簿からの実績収支の読み取り、計画データだけの保存、改訂番号検査。
- `model.js`: `state.planning` を追加（データモデル v9）。
- `src/app/99_nav_boot.part.js`: 資金計画タブへの遷移。
- `index.html`, `sw.js`: UI読み込みとPWAのオフラインキャッシュ。

## 計算の前提
- 実績連動月：家計簿のカテゴリ仕訳から収入−支出を計算する。カード引落と口座振替は新しい支出にしない。
- 特典利用収入は収入側に計上し、旧管理外ポイントは費用側から控除。返金など負の費用は符号を維持する。
- 進行中の月：記帳済み実績＋残期間の見込み（重複しないよう手入力）。
- 将来月：見込み余剰または収入−支出の詳細入力。未入力は0円扱いで確定せず、暫定と表示する。
- 別枠項目：「今回の計画で計上する」「月別見込みに含まれる」「実績に含まれる」「一部計上済み」「要確認」を区別する。
- 期首の口座残高・積立済額を新たな財源として自動加算しない。

## 保存 / 安全性
- `planning.html` のサンプルJSONは製品から除去。既存データ無しなら空の計画を作る。
- `state.planning` は独立。資金計画の編集で `state.transactions`・`state.accounts`・`state.goals`・`state.wishlist` は書き換えない。
- 家計簿から取り込んだ実績金額は派生値なので保存せず、閲覧時に再計算する。
- ブラウザ内の改訂番号とローカル保存の版を確認して競合保存を拒否する。
- `cloud.js` は既存 `updated_at` を条件にした更新（CAS）へ変更。書込みは直列化し、競合時・通信障害時は以降のクラウド同期を止め、端末内データを残す。SQL変更は不要。

## リリース前の未解決事項
2026-10-25に開発ブランチの `cloud.js` を、既存 `updated_at` を使う**条件付きUPDATE**方式へ変更しました。同じ新バージョン同士の別端末競合は古い保存を拒否します。

**残る注意点**：公開済みの古いページやPWAが従来の全状態upsertで書く場合、このチェックを通りません。公開前に実データをJSONバックアップし、すべての端末・タブを終了して新しい版で開き直す必要があります。同期停止時に残ったローカル変更は自動統合されません。クラウド「同期済み」を確認し、必要ならJSONバックアップを保存してください。**本番へのマージ・公開は引き続き別判断**です。

また、取引との自動照合、既存の積立・ほしいものとの相互リンク、口座残高による資金繰りは本バージョンの対象外です。

## 午後の家族相談で使う場合

- 単独 `planning.html` は家計簿・Supabaseから独立し、端末内保存（未許可の環境では編集可・JSON書出専用）で利用できます。
- 製品側の「資金計画」は独立HTMLを同一オリジンのiframeとして組み込む方式。家計簿実績の自動読取りができるのは製品側です。
- 家族相談では複数端末で同時編集せず、利用後はJSONエクスポートを控えてください。
- 今日の相談のために追加のDBテーブルやRLSを新設する必要はありません。

## 検証
```sh
python3 tools/build_app.py --check
node --check app.js
node --test tests/planning-v19.test.cjs
```

ブラウザではタブ起動、実績連動/手入力切替、大項目・内訳編集、Undo、プリセット・シナリオ複製、保存と再読込、PC/スマホ幅、複数端末競合を確認してください。
